# Tickets

Self-contained local issue tracker for the sign library (same format as Akimbo's). Everything lives in this folder.

## Layout

- `SGN-###-slug.md` — one ticket per file. The YAML frontmatter is the source of truth; the body is free markdown.
- `INDEX.md` — table of all tickets grouped by project. Regenerated by `tk.py index`; do not edit by hand.
- `tk.py` — helper (no dependencies). Optional: you can also just edit the files.

## Ticket format

```
---
id: SGN-004
title: One-line title
status: open | in-progress | blocked | done | wontfix
priority: P0 | P1 | P2 | P3
area: sources | extract | qa | fonts | layout | licence | docs | process
project: australia | usa | nz | uk | pipeline | repo | none
created: 2026-09-06
updated: 2026-09-06
source: manual | review-YYYY-MM-DD
---

## Summary      what is needed and why it matters
## Evidence     sources, URLs, files (verified)
## Fix          the concrete work
## Verify       how we know it is done
## Log          dated entries, newest last
```

Priority: P0 = wrong or missing official signs in a shipped pack, licence breach. P1 = a pack Russell's users need (Australian states, major US states). P2 = the rest of the roadmap. P3 = nit.

Projects: `australia` national + state packs · `usa` federal + state packs · `nz` TCD Manual pack · `uk` TSRGD packs · `pipeline` extractor/QA tooling · `repo` repo, docs and layout.

## Commands

```bash
python3 Tickets/tk.py list                      # open tickets, P0 first
python3 Tickets/tk.py list --project usa --status open
python3 Tickets/tk.py show SGN-004
python3 Tickets/tk.py new "Title" --priority P1 --area sources --project usa
python3 Tickets/tk.py set SGN-004 status in-progress
python3 Tickets/tk.py index                     # rebuild INDEX.md
```

## Working rule

- A pack or tool change starts by reading its ticket and ends by appending to its Log and setting its status.
- Findings discovered mid-task become new tickets, not silent fixes.
- Commit subjects carry the ticket id, e.g. `SGN-012 QLD: TC signs pack`.
- A ticket is `done` only when its Verify section has been checked, and the Log says how.
